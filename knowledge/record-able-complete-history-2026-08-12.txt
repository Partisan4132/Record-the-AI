Product Purpose
record-able is a Fabric client mod that records Minecraft gameplay directly from the active game
session. It captures frames, sends video to FFmpeg, supports game and microphone audio
where the platform makes those routes available, creates replay clips, manages a video library,
and provides in-game playback. The official project describes hardware acceleration, software
encoding, container choices, overlays, watermarks, auto clips, replay buffering, crash recovery,
deferred rendering, and compatibility behavior. [3]

V1-0.01: Initial Recording Foundation
V1-0.01 introduced the first version of record-able. Its published setup model required an
FFmpeg installation before recording. On the first recording attempt, the mod prompted the user
to install FFmpeg through an in-game installer. The published note described this as a user
approved one-time setup rather than an automatic download. [1]
The core idea established at this stage remains current: Minecraft frame capture is encoded with
FFmpeg and written as a video file without requiring an external screen capture application.

V1-0.02: Filters, Overlays, and First Privacy Controls
V1-0.02 expanded visual presentation. The published change notes list VHS, LCD Moire, and
CRT filters, with support for combining them. It added Speed Runner, VHS, VHS minimal, and
VHS full recording overlays. It also introduced an overlay editor and documented BetterShields
as an additional incompatibility to detect. [1]
Current descendants of this work include selectable overlay styles, configurable colors and
positions, an editor for visual elements, and presentation controls that can be applied to
recordings.

V1-0.03: Theme System
V1-0.03 replaced the prior interface styling with five theme presets: VHS, Cinema, Neon,
Minimal, and Classic. It added themed widgets, scanlines, film grain, glitch effects, vignettes,
redesigned main screens, a theme configuration screen with live preview, typewriter animations,
and loading indicators. [1]
The current settings still expose theme and overlay choices. Theme behavior must remain visual
only and must not silently alter recording, replay, or privacy settings.

V1-0.04: Bookmarks, Templates, and Simplified Controls
V1-0.04 introduced recording bookmarks, early automatic clips for achievements, deaths, boss
kills, and dimension changes, plus recording templates for Cinematic, Balanced, Streaming, and
PvP use cases. The published notes also describe settings cleanup, reduced audio setup
controls, automatic function-key conflict avoidance, and removal of the Cloth Config
dependency. [1]
The historical V1-0.04 default controls were Toggle Recording on minus, Pause or Resume on
equals, Open Settings on F9, Video Collection on F12, and an unbound bookmark action. Users

should use the current Controls screen as the final authority because current configuration can
change these defaults.

V1-0.05: Variant Structure and Microphone Reliability
V1-0.05 split the project into legacy, sandwich, and modern variants. The release notes added
microphone testing, microphone device cycling, noise suppression, silent microphone warnings,
and automatic microphone fallback. It also documented microphone and video synchronization
fixes, restoration of game UI in recordings, library cleanup, and a substantial packaged size
reduction. [1]
The current variant boundaries are more precise than the earlier historical wording. Current
legacy targets Minecraft 1.20.0 through 1.20.4, sandwich targets 1.20.5 through 1.21.11, and
modern targets 26.1 through 26.2 and compatible later releases.

V1-0.06: Auto Clips, Replay Compatibility, and Management
Screens
V1-0.06 was a broad feature release. Published notes describe kill clips for melee, projectile,
spear, and modded weapons; kill montages with preroll, event, and postroll segments; a Clips
collection; trigger switches for deaths, dimensions, achievements, kills, and boss kills; automatic
clip folders; and audio controls for automatic clips. [1]
It added a bridge for Flashback and Replay Mod, automatic recording behavior around replay
activity, microphone and push to talk support in legacy and sandwich, separate game and
microphone tracks, audio chapters, comprehensive scrolling, draggable collection scrollbars,
video and clip protection, a draggable microphone indicator, movable overlay elements, a
watermark editor, a storage screen, gallery sorting, per-category chat notifications, performance
presets, optimized NVIDIA settings, and software queue safeguards. [1]
The update also documented repairs for world-leave recording persistence, audio delay, missing
microphone overlay state, kill montage deadlock, replay bridge audio, encoder selection
reversion, and several layout issues. [1]

V1-0.07: Android and Device-Aware Recording
V1-0.07 introduced the first documented Android-focused feature set. The published notes
include Android launcher compatibility, gallery saving, Android settings, compression, low
storage warnings, sharing, FFmpeg setup support, and Android troubleshooting. It also added
Classic, VHS, and Synthwave overlay skins, Android, low-end, mid-range, high-end, and NASA
performance presets, feature search, WebM and MOV formats, improved overlay panels, a

visible replay-buffer switch and duration control, improved projectile and trident detection, and
mobile collection layout repairs. [1]
The published Android support was experimental. Current V1-0.11 preserves that distinction by
detecting Android capabilities at runtime, guarding GLES readback behavior, using executable
runtime recovery for FFmpeg, and reporting audio capability states precisely.

V1-0.08: Capture Performance and Censor Workflow
V1-0.08 focused on recording performance and Android capture compatibility. The official notes
describe reduced render-thread frame capture cost, adaptive recording FPS, device profiles,
performance statistics, a GLES texture-readback route for black recording cases, an FFmpeg
welcome screen, a live censor editor, a censor overlay hotkey, capture diagnostics, a Bake in
Overlay choice, and right-click backward cycling for multi-option controls. [1]
Current V1-0.11 continues this direction. The capture path keeps PBO storage allocated after
setup, caches selected driver state, avoids an Android-wide GPU finish wait, moves
synchronous conversion away from the render thread, and uses bounded workers for replay
processing.

V1-0.09: Sharing, Background Loading, Voice Chat, and
Compatibility
V1-0.09 added sharing reliability work, including upload error messages, retention options, and
a custom recording filename field. It added asynchronous Video Collection loading, a custom
toast system, keybind documentation, microphone drift work, Android volume gain, optional
Simple Voice Chat capture, background frame conversion, a standalone replay buffer, lag-safe
key handling, Apple Silicon FFmpeg support, Vulkan compatibility warnings, a custom output
folder picker, and several Minecraft version compatibility fixes. [1]
The current source retains the platform-aware FFmpeg resolver, output folder selection, share
integration, compatibility bridge, and background gallery preparation. Current source hardening
also routes offline renderer, storage manager, and chapter manager FFmpeg checks through the
same platform-aware resolver.

V1-0.10: Recovery, Deferred Capture, Player, and Disk-Backed
Replay
V1-0.10 added crash recovery. Interrupted recording artifacts can be found on the next launch
and remuxed to a playable container or discarded. It introduced Deferred Render mode, where
frames are captured at 5, 10, 15, 20, or 30 FPS for lower gameplay cost and rendered later at

30, 60, or 120 FPS with no interpolation, duplicate interpolation, or motion-compensated
interpolation. [2]
V1-0.10 also added the Pending Renders screen, the Open Pending Renders keybind, an ingame player with play, pause, seek, speed, volume, background frame extraction, a startup
compatibility checker, reliable projectile kill detection, a disk-backed replay buffer using rolling 32
MB files, and the Open Recording Settings keybind. Its repairs included duplicate blur
protection, low disk replay sequencing, duplicate projectile clip prevention, microphone start
timing, and microphone timestamp diagnostics. [2]

V1-0.11: Current Source Baseline
V1-0.11 is the current maintained baseline. Its documentation reflects the active source and
validated maintenance work rather than a published external release note.

Complete Current Feature Reference
Recording and Video Controls
The main settings allow recording resolution, frame rate, bitrate, quality, container, encoder
selection, maximum file size, output folder, automatic recording behavior, recording notifications,
and overlay configuration. FFmpeg is required for encoding. The installation flow validates
available copies before offering a download and supports recovery of downloaded binaries on
Android.
Supported user-facing encoder choices include software H.264 plus detected hardware
encoders such as NVIDIA NVENC, AMD AMF, and Intel Quick Sync. Container controls include
MP4, MKV, MOV, and WebM. High resolution, high frame rate, long duration, and high quality
settings increase GPU, CPU, memory, storage, and encoder load.

Audio and Microphone Controls
Game audio capture prefers OpenAL loopback because it captures Minecraft’s mixed audio
directly. Desktop systems can also use operating-system loopback sources when supported.
Microphone recording supports selectable devices, a microphone test, noise suppression, gain,
push to talk, separate game and microphone tracks, and optional voice-chat inclusion.
Android audio behavior depends on the launcher. A supported but inactive loopback route is
normally ready to be requested at recording start. A launcher without the OpenAL loopback
extension cannot provide direct game audio through that route. Microphone capture and videoonly recording remain available.

Replay, Clips, and Markers
The replay buffer keeps recent gameplay for manual saving. It is disk-backed, so long buffers do
not need to remain in JVM heap memory. Bookmarks mark timestamps in active recordings.
Auto clips respond to enabled triggers, and kill montage behavior combines contextual footage
with an event segment. Clip entries can be organized, sorted, protected, and unlocked.

Deferred Capture and Pending Renders
Deferred capture separates capture time from final render time. It records raw frames at a lower
rate during gameplay and renders the final file later. Pending Renders lists queued sessions and
lets users render individual sessions, render all compatible sessions, or delete sessions. This is
appropriate when visual smoothness is more important than real-time output and when storage
capacity is available.

Video Collection and Player
The Video Collection shows supported recordings, thumbnails, metadata, sort controls, folder
actions, lock state, delete confirmation, copy-path, share actions, and playback. Temporary
conversion files are excluded from normal gallery entries. The player supports a progress bar,
seek, speed control, volume, frame preview, and platform-aware audio routing.
On desktop, ffplay can handle playback audio while Minecraft shows decoded frames. If ffplay is
unavailable, desktop fallback can use the system video player. Android keeps the player inside
Minecraft and uses an in-game preview. When internal audio decoding is active, the frame clock
follows OpenAL presentation progress rather than an unrelated wall clock.

Overlays, Themes, Watermarks, and Censoring
The mod provides recording overlays, position controls, scale control, timer and status visibility,
theme choices, VHS controls, mouse-pointer rendering, watermark management, and HUD
hiding. Censor tools create privacy regions and can be toggled through a keybind. Censor
regions can be edited in a dedicated screen and applied over gameplay and supported user
interfaces.

Storage, Recovery, and Sharing
Disk space protection warns before recording fails. Storage management exposes cleanup
behavior. Recovery detects interrupted recording artifacts and offers remuxing. Output folders
are configurable. Sharing can upload compatible recordings and surfaces user-readable network
errors. The current resolver centralizes FFmpeg detection for recording, storage, chapters, and
offline processing.

Compatibility
record-able integrates with Mod Menu and can expose its screen title to CraftPresence when
that optional dependency is present. It contains replay compatibility behavior for Flashback and
Replay Mod and warns about known conflicts. The mod supports Fabric client environments
only.

Daily Documentation Procedure
Each daily documentation run must inspect current source changes, translation resources, tests,
and outputs. It must retain this historical baseline, add newly confirmed feature or repair entries,
update the current keybind table if source defaults change, and clearly separate published
historical facts from current development changes. The daily output must include a dated TXT
file and a dated PDF file for the user. It must not publish to GitHub unless the user explicitly
changes the delivery requirement.
